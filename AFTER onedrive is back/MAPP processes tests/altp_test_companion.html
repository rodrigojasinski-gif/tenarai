ALTP / MAPP — Painel de Apoio aos Testes

Referencia pratica para rodar os testes E2E no RADD (dawapp7017l). Story AES-XXXX.

Config (1 arquivo) altp_ftp_data.ksh — define tudo abaixo numa linha so
ALTP_FTP_DATA /nas/mdev/OEM_Repair_Doc_Repository/ftpdata/mdev temporario / teste
ALTP_DIR $ALTP_FTP_DATA/altp
ALTP_NAPA_DIR $ALTP_FTP_DATA/altp/NAPA
ALTP_INTRPT_DIR $ALTP_FTP_DATA/altp/Internal_Rpts
ALTP_CUSTRPT_DIR $ALTP_FTP_DATA/altp/Customer_Rpts
arquivo de entrada round-trip (batch escreve, analista revisa, batch le) relatorio / saida processo batch acao humana

1. Visao geral — as 3 cadeias compartilham o mesmo motor

Os wrappers (xamr*) sao "lancadores". O trabalho real esta em 3 sub-scripts — xamref / xamupd / xamrpt — reaproveitados pelas 3 cadeias. Editando esses 3 (+ xam200), voce cobre tudo.

Cadeia KEYSTONE

XAMR100 → xamref.ksh reformat
XAMR101 → xamupd.ksh update
XAMR102 → xamrpt.ksh report

Cadeia NAPA

XAMR200 → xam200.ksh + xamref.ksh
XAMR201 → xamupd.ksh
XAMR202 → xamrpt.ksh

Cadeia MULTI-SUPPLIER

XAMR900 → xamref.ksh
XAMR901 → xamupd.ksh
XAMR902 → xamrpt.ksh

2. Cadeia KEYSTONE passo a passo — o teste E2E

Cada caixa azul = um job que voce dispara. Cada caixa laranja = uma acao sua (simulando o analista). Verde = le, vermelho/roxo = escreve.

Fluxograma

Detalhe passo a passo

0. Preparo — Chuck + voce
Chuck gera o arquivo no Windows e te manda. Voce copia pro folder de teste pelo lado Linux.
resultado
keystone_combined.txt$ALTP_DIR/
↓
1. XAMR100 — reformat xamr100.ksh → xamref.ksh
Le o combined, limpa, carrega no Oracle (PKG_ALTERNATE_PARTS_LOAD_TRANS), gera o refproc + relatorios.
le
keystone_combined.txt$ALTP_DIR/
escreve
keystone_refproc.txt$ALTP_DIR/ keystone_referrs.txt$ALTP_INTRPT_DIR/ keystone_refsum.txt$ALTP_INTRPT_DIR/
↓
2. Revisao do analista (simulada)
No teste: so confirmar que da pra abrir e ler o refproc. Em producao o analista edita e salva de volta no mesmo lugar.
arquivo
keystone_refproc.txt$ALTP_DIR/ (revisado, mesmo lugar)
↓
2b. XAMR101 — update xamr101.ksh → xamupd.ksh
Le o refproc revisado, valida part numbers, atualiza part_altpart_xref no Oracle, gera o rpt_prov + relatorios.
le
keystone_refproc.txt$ALTP_DIR/
escreve
keystone_rpt_prov.txt$ALTP_DIR/ keystone_partver_sum.txt$ALTP_INTRPT_DIR/ keystone_updt_sum.txt$ALTP_INTRPT_DIR/
↓
3. Revisao do analista (simulada)
Mesma ideia: confirmar que da pra abrir o rpt_prov.
arquivo
keystone_rpt_prov.txt$ALTP_DIR/ (revisado, mesmo lugar)
↓
3b. XAMR102 — report xamr102.ksh → xamrpt.ksh
Le o rpt_prov revisado, gera relatorios de excecao por provider, monta o zip e envia pros suppliers (email ou Mitchell FTP — NAO prod3nt).
le
keystone_rpt_prov.txt$ALTP_DIR/
envia (fora do escopo prod3nt)
mitch_exc_rpts.zipemail / Mitchell FTP (scp) — sem mudanca
Atencao: os arquivos round-trip (vermelho) ficam em $ALTP_DIR/ — mesma pasta onde sao escritos E lidos. O analista trabalha sempre nesse mesmo lugar, igual era no prod3nt. Nada de mover arquivo entre pastas.

5. Ordem de execucao do teste

  • 1
    Deploy: copiar altp_ftp_data.ksh + os 9 scripts pro diretorio de scripts do RACE no RADD. chmod +x, conferir file *.ksh (sem CRLF).
  • 2
    Rodar ./setup_test_env.sh — cria altp/, altp/NAPA/, altp/Internal_Rpts/, altp/Customer_Rpts/ e testa o write.
  • 3
    Pedir keystone_combined.txt pro Chuck. Copiar pra $ALTP_DIR/.
  • 4
    Redirecionar emails de teste: editar zxamrefa.prm, zxamupda.prm, zxamrpta.prm pro seu email (backup antes).
  • 5
    Rodar xamr100.ksh. Conferir: refproc + referrs + refsum criados. Log sem erro.
  • 6
    Conferir/abrir keystone_refproc.txt (simula revisao do analista).
  • 7
    Rodar xamr101.ksh. Conferir: rpt_prov + partver_sum + updt_sum criados. Oracle part_altpart_xref atualizada.
  • 8
    Conferir/abrir keystone_rpt_prov.txt (simula revisao do analista).
  • 9
    Rodar xamr102.ksh. Conferir: zip gerado, email de teste recebido.
  • 10
    Coletar evidencias (logs de $RACE/log/, screenshots, ls -la das pastas). Restaurar os .prm de email.

XAMR200 — parte 2: xamref.ksh
Mesmo motor da Keystone, agora com qualifier "napa". Le napa_combined, gera napa_refproc. Dai segue igual: XAMR201 (xamupd), XAMR202 (xamrpt).

Depois do XAMR200, a cadeia NAPA usa os mesmos xamupd/xamrpt da Keystone — so muda o qualifier.
